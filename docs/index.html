01 / Wally Wallet

A small wallet.
Real controls.

Create wallets, receive coins, check confirmed balances, sign payments, and send them to peers. All from your terminal.

Start small. Wally is experimental SPV software. It verifies headers and transaction inclusion, not full consensus. It is not a full validating node.
01 Keys encrypted at rest
Argon2id and ChaCha20-Poly1305 protect your wallet file. Your password unlocks it locally.
02 Direct peer-to-peer sync
No Bitcoin Core or Dogecoin Core installation required. Wally downloads headers and scans blocks from network peers.
03 Payments you can retry
Pending transactions stay saved. Rebroadcast the exact signed payment instead of creating another one.
04 Backups you control
Keep your wallet JSON, password, and pending-payment state safe. There is no account recovery or password reset.

03 / Get started

Open a terminal.
Build it yourself.

Start in your local Wally source checkout. No hosted signup, browser wallet, or service token required.

>_

Wally Wallet

Rust 1.89+ and a C compiler

# build and install the CLI
cargo install --path . --locked

# create and sync a Bitcoin wallet
wally init --coin bitcoin
wally receive bitcoin
wally sync bitcoin
wally balance bitcoin

Creation asks for a password of at least 12 characters. Wallets default to ~/.wally/. First sync can take a long time and use substantial bandwidth.

Before your first payment

Use small amounts. Back up your wallet JSON and keep the password separately. After payments, back up the state file with Wally stopped. Fees are fixed rates, not live congestion estimates. Peer handoff does not guarantee confirmation.

wally rebroadcast bitcoin

If a payment times out, check its transaction ID before trying again. Rebroadcast the saved payment rather than sending a duplicate.

W

Wally Coin

The same generated WLY project on every node

cd wly-coin
./build.sh
./node -daemon
./wallet init --coin wly
./wallet receive wly

# replace the placeholder with your address
./mine <receiving-address> 101
./rpc getblockchaininfo

Builds need Rust 1.89+, CMake 3.22+, C++20, Boost 1.73 to 1.89 headers, and libevent 2.1.8+ development headers. The node binds to localhost by default.

Add the second wallet peer

Wallet sync needs two distinct peer IPs. Start another node from this same project before checking your WLY balance.

mkdir -p data2
./bin/wly-node -datadir="$PWD/data2" \
  -port=19335 -rpcport=19337 \
  -bind=127.0.0.2:19335 \
  -connect=127.0.0.1:19335 -listen=1 \
  -dnsseed=0 -fixedseeds=0 -daemon
./wallet --peer 127.0.0.1:19335 \
  --peer 127.0.0.2:19335 balance wly
Inspect blocks and addresses

For projects with the generated viewer, run ./viewer and open http://127.0.0.1:8080. Python's standard library serves the page; the native CLI reads the chain.

Block searches show transaction details. Address searches show confirmed unspent outputs, not full history. They ignore mempool changes and can include immature mining rewards.

Keep the same chain

WLY is a separate generated project, not an extra coin inside your original Bitcoin or Dogecoin wallet. Get the same generated files to join this WLY chain. Running create-coin.sh again creates a different genesis and network.
